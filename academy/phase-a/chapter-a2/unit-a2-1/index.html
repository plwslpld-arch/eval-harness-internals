从抽象质量到可测量构念

把“可靠、安全、专业、有据”转换为可审查的构念、维度、观察、代理、规则和有限结论，并显式处理测量误差、可靠性与效度。

本页是完整的独立教学材料，但仍只描述设计合同：不表示真实测量、Scorer、Harness、可靠性或效度证据、生产运行、发布授权或个人掌握已经成立。

1. 学习目标与边界

本单元训练六件事：分清测量链中的九个对象；识别构念代表不足和无关因素污染；建立随机、系统和交互误差模型；为四类可靠性设计研究；用五类证据建立统一效度论证；保留 passed / failed / uncertain / unscorable / invalid 五种状态。

边界止于测量设计。这里不会运行 Target、实现 Scorer/Harness、产生真实 Score、Metric 或 Estimate，也不会把计划中的研究写成已经观察到的证据。

2. 测量不是“给系统一个数字”

业务愿望 → Construct → Facet → Observable → Proxy / Indicator
→ Measurement Rule → Score Record → Metric / Estimate → Claim

Construct（构念）

真正想理解、但不能直接读取的抽象质量。

Facet（维度）

构念中不可相互替代的组成部分。

Observable（可观察事实）

运行后可验证的事件、状态和证据。

Proxy / Indicator（代理 / 指标）

用来间接代表构念的信号，不是构念本身。

Measurement Rule（测量规则）

规定证据组合怎样映射到裁决状态。

Score（评分记录）

一个明确评分单位的一次裁决，不是总体表现。

Metric（指标合同）

定义怎样估计总体中的量，不是一次计算值。

Estimate（估计值）

在版本化数据与分析合同下得到的一次结果。

Claim（结论）

当前证据在 Target、总体、场景和时间边界内最多允许说什么。

例如“退款 Agent 可靠”至少涉及任务有效性、授权合规、状态安全、恢复、升级和回复—状态一致性；任务完成率不能替代这些维度。

3. Construct、Facet 与 Observable

操作化首先要写构念定义、明确排除项（exclusions）和决策相关性，再拆分 Facet。退款授权合规可拆为有效审批、金额/地区处于授权范围、授权先于副作用；相应事实包括审批事件、政策版本、工具参数、幂等键和账本终态。

对有副作用的 Agent，通常采用以下权威顺序：

权威环境终态 > 可验证工具结果 > 行为轨迹 > 最终文本声明

最终文本说“退款成功”不能覆盖资金账本；权威顺序由领域责任人声明，不能由 Judge 根据语言流畅度改写。

4. Proxy 的两种核心失效与 Goodhart 风险

Construct Underrepresentation（构念代表不足）

指标只覆盖一部分构念。回复正确但账本重复写入、合同标签正确但 span 不存在、知识回答有引用但 ACL 违规，都是“指标好、构念仍差”。

Construct-Irrelevant Variance（无关因素污染）

OCR、附件完整性、字符偏移、文本长度或 Judge 风格偏好改变分数，却不是目标能力变化。关键输入缺失时应是 unscorable，不是零分。

Goodhart’s Law（古德哈特定律）

代理指标一旦成为优化目标，可能不再代表原构念。只压低拒答率会鼓励无证据猜测，应联合 coverage、有据性、正确弃权、ACL 安全和人工负担，并让关键泄露不可补偿。

审查代理时必须回答：为何代表构念、覆盖和遗漏什么、受何种污染、有哪些正反例、最多支持何种 Claim。

5. Measurement Error（测量误差）

Observed Score = Construct-related signal + Random error + Systematic error + Context interaction
  • Random error（随机误差）：方向不固定，合理重复可降低部分影响。
  • Systematic error（系统误差）：稳定偏向错误方向；重复再多只会稳定地测错。
  • Interaction（交互误差）：Target 与语言、身份、合同类型、故障或环境组合产生差异。
来源典型问题设计响应
Target采样、检索排序、路径或身份漂移区分自然变化与不同 Target
Harness未重置、Trace 截断、重试扩大分母隔离、完整性、Trial/Attempt 合同
Sampling有限样本或抽样框偏差总体、权重、依赖与区间
Reference政策过期、漏标、合理多值版本、未知、集合与仲裁
ScorerRubric 模糊、Judge 偏差、规则错误Anchor、扰动、独立验证与拒判
Aggregation删除 timeout、伪独立、平均补偿关键风险分母、依赖、coverage 与非补偿规则

增加样本量只能缩小部分抽样误差，不能修复错误构念、失效代理、错误 Reference 或系统偏差。

6. Reliability（可靠性）：什么条件下的一致

维度问题
Repeatability（重复性）尽可能相同条件下重复是否一致？
Reproducibility（可复现性）允许的机器、Worker、批次或重放环境变化后能否复现？
Intra-rater reliability（评分者内可靠性）同一评分者不同时间对同一证据是否一致？
Inter-rater reliability（评分者间可靠性）不同评分者对同一单位和证据是否一致？

Agreement（绝对一致）不等于 Correlation（相关）。两位 Judge 始终相差 2 分，排序相关可以很高，但阈值决定可能相反。

  • 二分类：混淆矩阵、关键类别召回、Kappa；有序等级：Weighted Kappa。
  • 连续分数：绝对一致型 ICC；排序：排序相关加成对决策一致。
  • 多评分者或缺失评分：Krippendorff’s Alpha。
  • Span：版本一致前提下的边界重叠；Set-valued：允许集合覆盖。
  • 结构化轨迹：事件身份、顺序和不变量。

样本还应覆盖正常、边界、关键失败、缺证、合理多值和对抗 Anchor；保存原始评分和分歧，不能只保留仲裁后标签。

7. Validity（效度）：解释和使用为何成立

效度不是给工具贴一个“有效”标签，而是对分数解释和使用的统一论证。

证据来源核心问题
Content（内容）是否覆盖重要 Facet、边界和关键失败？
Response process（反应过程）分数是否由预期观察和裁决过程产生？
Internal structure（内部结构）维度关系是否符合构念模型和非补偿规则？
Relations（与其他变量关系）是否关联权威标准且不追随无关特征？
Consequences（后果）使用测量会不会激励规避、隐藏伤害或扩大不公平？

与专家一致率高，只是 relations 与 reliability 的部分证据；如果专家 Reference 单值化了合理多值，或共享同一盲点，仍不能建立效度。

8. 五种结果状态

passed

观察与规则充分，满足声明条件。

failed

充分证据确认违反规则。

uncertain

证据存在，但合理边界不足以单值裁决。

unscorable

缺少形成合法 Score 的关键观察。

invalid

身份、协议、血缘或权威错误使证据不可使用。

failed 不等于 unscorable；uncertain 不能取平均；invalid 不代表 Target 表现差。后续 Metric 和 Gate 必须保留这些差异。

9. Construct Operationalization 完整流程

  1. 写清谁依据证据决定什么。
  2. 定义 Construct 和禁止解释。
  3. 拆分不可替代 Facet 与 criticality。
  4. 写正例、反例、边界、缺证和关键失败。
  5. 指定 Observable、捕获条件和权威顺序。
  6. 为 Indicator 写代理理由、代表不足和污染风险。
  7. 定义 Measurement Rule 与五种 outcome。
  8. 写改变目标因素时结果应改变的 Counterfactual。
  9. 写改变无关因素时结果应稳定的 Invariant。
  10. 建立六类 Error Model 和残余 Claim 限制。
  11. 预声明 Reliability 的对象、条件、重复、统计和分歧处理。
  12. 建立五类 Validity Evidence 要求与当前状态。
  13. 用 Measurement Quality Gate 检查覆盖、代理、误差、可靠性、效度、边界和追踪。
  14. 只有物化证据满足预声明规则后才扩大 Claim；设计完成必须保持 blocked。

10. 三个贯穿案例

退款 Agent

审批、工具、幂等键和账本终态优先；授权合规、状态安全和适当升级分别进入指标和规则。未授权成功写入是不可补偿失败。

完整案例

合同审查 Agent

关键风险识别、原文有据性和校准升级分别测量；OCR、附件、字符偏移和合理多值 Reference 必须与法律判断分离。

完整案例

企业知识助手

可回答性、有据性、当前性、访问隔离和适当拒答分别进入指标；ACL 必须覆盖检索、上下文、缓存和输出。

完整案例

三个案例都只是合成设计合同：Reliability 和 Validity 仍是 planned / not-observed，Measurement Gate 均为 blocked。

七项全部关键的测量就绪检查。

12. 十个常见误区

  1. 准确率高不等于可靠性；它可能只覆盖任务有效性。
  2. 有引用不等于有据；还要验证 claim-span、当前性、运行取得和 ACL。
  3. Judge 五次一致不等于有效；可能稳定地测错。
  4. 高度相关不等于高度一致；系统偏移会改变阈值决定。
  5. 确定性 Scorer 仍需验证规则、输入和版本。
  6. 更多样本不能修复坏 Proxy，只会更精确地估计错误对象。
  7. 缺证不能记零分；零分是充分证据下的失败。
  8. 总体高分不能补偿 ACL 泄露等关键风险。
  9. 专家一致率高不能单独证明 Validity。
  10. Measurement Quality Gate ready 只代表测量证据资格，不代表系统可上线。

13. 最终检查表

  • □ Construct、Facet、exclusions 与 decision relevance 已写清。
  • □ Observable 是可验证事实，而非 Target 自述。
  • □ 每个 Indicator 都有 proxy rationale、污染和代表不足风险。
  • □ 权威顺序、五态、反事实和不变量完整。
  • □ Target/Harness/Sampling/Reference/Scorer/Aggregation 六类误差均已登记。
  • □ Random、systematic 与 interaction 没有混用。
  • □ 四类 Reliability 的条件、统计、Anchor 和重复已预声明。
  • □ Agreement 没被 correlation 或总体一致率替代。
  • □ 五类 Validity Evidence 都连接到解释和使用。
  • □ Goodhart 风险与使用后果已经审查。
  • □ Claim 不超过 Target、总体、场景、时间和证据状态边界。
  • □ 引用双向闭合，planned/not-observed 没有伪装成已验证。

14. 明确证据边界

本候选包只证明课程、八个模板、三个合成案例和内部引用合同已经形成。它不证明真实测量已发生，不证明 Reliability 或 Validity Evidence 已物化，不证明 Scorer、Judge、Harness、数据、Score、Metric、Estimate、Gate 或生产系统就绪，不证明发布安全，也不证明任何个人已掌握本单元。

一句话：可信测量不是寻找一个看起来合理的数字，而是证明观察、代理、规则和统计结果为什么能在明确边界内代表目标构念，同时诚实保留遗漏、污染、误差和不能支持的结论。
