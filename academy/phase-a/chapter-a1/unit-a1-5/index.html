从任务与场景到评测数据

把任务合同转换为有总体、有权利、有参考、有独立性、可版本化且能被质量门审查的数据资产。

核心命题：样本数量不产生代表性，标签一致不自动产生真值，随机按行切分不产生独立性，数据 ready 也不表示系统已经通过真实评测。

01 · 从 Task Spec 到数据资格

Task / Scenario → Dataset Charter → Source Register → Sampling Plan → Reference Standard → Annotation Protocol → Split Manifest → Dataset Manifest → Data Quality Gate → 后续 Trial

本单元止于数据准备资格。它不运行候选系统，不实现 Scorer 或 Harness，不计算 Metric，也不执行系统发布 Gate。

02 · 总体、单位、抽样框与三分区

目标总体定义希望结论覆盖的任务机会；分析单位定义一条结果对应什么；父单位描述样本依赖；抽样框是当前真正可枚举且有权使用的单位。抽样框缺口必须记录影响、责任人、动作与状态。

分区用途不能声称
Distribution保留总体构成与自然分母抽样设计不足时不能推广总体
Challenge富集边界、异常、对抗与关键风险不能估计生产自然发生率
Regression冻结事故、缺陷与重要边界不能代表总体分布

03 · 来源、血缘、授权与抽样

每项来源都要登记 producer、snapshot、采集方法、父资产、转换版本、批准目的、到期、隐私、许可、访问、保留和限制。公开可访问不等于可无限复用，去标识也不自动消除权利与再识别风险。

Sampling Plan 同时记录 target count、actual count 和 met/gap/blocked，但数量不能单独使 critical risk ready；还需语义覆盖、Reference、标注质量与泄漏检查。

04 · Reference Standard / Oracle

Authoritative state
账本、ACL、有效政策或唯一原文。
Set-valued reference
保留多个满足合同的答案或合理解释。
Invariant
没有唯一答案时检查必须保持或改变的关系。
Expert judgment
由合格领域专家依据版本化材料判断。

来源冲突、材料缺失和专家分歧必须保留为不确定性，不应为了“干净标签”强制压成二元真值。

05 · 独立盲标、分歧与仲裁

固定协议 → 隐藏候选与 split → 两位标注者独立提交 → 保留原始标签 → 分类分歧 → 独立仲裁 → 输出理由与证据链接

一致率高不等于 Reference 有效；多数票也不能消除来源冲突。若分歧暴露协议缺陷，应暂停批次、修订协议并评估重标范围。

06 · 五类泄漏与受保护视图

边界必须共同隔离的对象
Parent基础案例与其反事实、同义和故障变体
Entity订单、交易包、身份或业务状态链
Document修订、附件、切块和派生问答
Template生成模板、标准条款、攻击模板与近重复
Time截点后的标签、政策、ACL 和结果

先计算依赖闭包，再把组分配到 split。Target 和 Harness 视图不得读取 reference、annotation 或 expected；只有 Scorer 在候选观察产生后按最小字段访问 Reference，Audit 则按审计目的受控访问。

07 · 不可变版本、漂移、刷新与质量门

内容、schema、来源、Reference、协议或 split 改变都要发布新 immutable ID，不原地覆盖。总体构成、事故、政策、ACL、来源 schema、标注分歧和授权到期都可触发刷新。

决定数据动作
ready只允许进入声明范围的后续 trial 准备
partial只继续充分且可隔离的子范围
blocked关键证据缺失，停止 trial
invalid授权、身份、Reference 或泄漏缺陷使版本不得使用
检查状态使用 passed/partial/blocked/failed；整体决定才使用 ready/partial/blocked/invalid。每项证据必须说明 semantic basis，不得由 sample count 冒充。

09 · Task-to-data review

  1. 定义总体、单位、父级、抽样框与 gap。
  2. 登记来源的 provenance、lineage、授权、隐私、许可与保留。
  3. 分开 distribution、challenge、regression 的选择与分母。
  4. 建立权威、多值或不变量 Reference。
  5. 执行独立盲标、保留分歧并独立仲裁。
  6. 按五类依赖闭包切分，检查未来信息。
  7. 发布不可变版本与四种字段视图。
  8. 运行数据质量门；blocked 或 invalid 时停止 trial。

明确边界

本单元不实现 Scorer、Judge、Harness 或 Trial 调度，不计算 Metric 或统计推断，不执行系统发布 Gate。候选包不证明真实数据完成、系统质量、生产适用性或个人能力。
