从业务需求到评测问题

把业务愿望转换为明确决定、利益相关方影响、风险、构念、评测问题和证据要求，形成可以审计的 requirements-to-evidence 链。

01 · 从愿望到证据

“全员上线”“零幻觉”“像专家一样”表达价值和压力，却不能直接成为验收标准。可靠设计从待批准决定开始。

业务愿望 → 产品目标与责任边界 → 决定 → Intended / Prohibited Use → Stakeholder-impact → Risk taxonomy → Construct → Evaluation Question → Evidence Requirement → Traceability → 决策动作

这条链要双向成立：每个关键风险向前都有证据和动作；每个指标向后都能解释它代表什么构念、控制什么风险、支持什么决定。

五类核心资产是一条控制链

资产职责主要输出
Evaluation Charter锁定谁决定什么，以及允许和禁止的用途决定、Target、范围、结果类型与限制
Stakeholder-impact mapping解释系统行为会沿什么路径影响谁影响链、责任人、控制与伤害路径
Risk taxonomy统一失败域、严重性、容忍度和不可补偿规则可验证的风险陈述
Construct operationalization把可靠、安全、专业变成有边界的属性正反边界例、观察、参考标准与限制
Evidence Requirement声明什么证据质量足以回答问题数据、场景、观察、评分、充分性与补证动作

它们会相互回写：新发现的受影响方会改变 Charter 和风险；构念不可观察时要补建证据能力或返回 Inconclusive；子范围无法隔离时也不能使用 Conditional Pass。

同一句模糊需求，导出三套设计

三个团队都说“这个 Agent 要可靠，可以上线”，但 Agent 改变世界的方式不同，所以不能共用一项可靠性准确率。

推导环节退款 Agent合同审查 Agent企业知识助手
决定是否允许在限定范围自动写入退款是否允许做律师复核前的首轮筛查是否允许员工在批准知识域获取信息回答
关键风险未授权退款、重复写账、漏升级重大漏检、伪造原文、责任越界无依据或过期制度、ACL 泄露、流程越界
关键构念政策合规、状态安全、适当升级关键风险召回、原文定位、校准升级可回答性、有据性、新鲜度、访问隔离
决定性证据审批、工具轨迹、幂等键、账本差异专家金标、风险类别、原文 span、候选负担文档版本与 ACL、检索上下文、主张—证据 span
失效代理回复文本正确率总标签准确率或“像律师”评分引用率、FAQ 正确率或咨询量下降

同一句话最后分别需要状态化 Sandbox、专家合同金标和多身份版本化知识环境；需求不是直接翻译成指标，而是经过决定、影响、风险、构念和证据五次收窄。

五种句子必须严格分开

层次规范含义知识助手示例
业务愿望组织希望发生的价值方向，不是可证伪门禁希望员工更快获得制度信息并减少重复咨询
产品目标产品输出如何改善用户与业务结果，并受 guardrail 约束提供当前制度的自助信息回答，且不得泄露受限信息
风险陈述触发、失败机制、受影响方、伤害、容忍度、观察与动作受限文档进入普通员工上下文导致泄露；确认即阻断
决策问题责任人依据证据在候选动作中选择什么允许两个知识域、阻断、补证还是只开放子范围？
评测问题针对 Target、总体、场景和构念提出可由证据回答的问题不同身份同问时，全路径是否始终满足访问隔离？

愿望和目标说明为什么值得做；风险说明什么不能接受；决策问题说明证据将改变什么动作；评测问题说明要观察什么才能回答决定。指标只是后续证据摘要，不能替代任何一层。

02 · 决定、用途与对象必须一致

含混表达可评测决定
退款 Agent 能否上线？是否允许候选版本在声明地区、政策与金额范围内自动执行退款，其余请求升级？
合同 Agent 达到律师水平吗？是否允许对声明合同类型执行首轮筛查，并由律师复核带原文定位的候选风险？
知识助手能否全员使用？是否允许正式员工在批准知识域中获得基于当前授权文档的回答？

Intended Use 声明用户、任务、环境和输出；Prohibited Use 声明不得处理的身份、数据、动作和正式责任。Evaluation Target 必须包含实际链路的身份、ACL、检索、模型、工具、环境状态与日志。

对象漂移会使结论失效：裸模型问答不能证明完整 Agent 可执行，管理员身份测试不能证明普通员工 ACL 安全。

03 · Stakeholder-impact 与风险

除直接用户外，还要识别数据主体、决策对象、资产负责人、运营者与治理角色。每一方都要连接价值、潜在伤害、控制、证据和责任人。

风险域典型问题
任务与事实错答、漏答、无依据主张、引用误导
权限与隐私越权读取、敏感推断、日志泄露
行动与状态错误工具、重复副作用、状态未知仍执行
人机责任不当自动决定、漏升级、人工控制无效
安全与运营提示注入、依赖异常、延迟与恢复失败
治理与证据版本不明、证据污染、不可重放、责任不清

风险陈述应包含触发、失败机制、受影响方、伤害、严重性、容忍度、可观察证据、控制和动作。关键权限、资金和权益风险通常不可由平均分补偿。

04 · 从抽象词到构念和评测问题

构念操作化必须给出定义、相邻构念区别、正例、反例、边界例、分析单位、观察、参考标准、评分限制和不能推出的结论。

有据性 ≠ 有引用。关键原子主张需要被系统实际获得、当前有效且用户有权访问的证据支持。引用数量只能作为诊断信号。

评测问题可写为：“对于【总体与场景】，系统是否【满足构念】，依据【参考标准与观察】判定；结果支持【什么决定】？”评分方法不是评测问题本身。

05 · Evidence Requirement 与追踪

  1. 来源与代表性：真实流量、专家构造和风险枚举各自承担什么作用。
  2. 场景矩阵：常规、边界、异常、身份、时间、高风险低频和对抗。
  3. 参考标准：真值责任人、版本、分歧、仲裁和不确定标签。
  4. 完整观察：答案、引用、检索、轨迹、工具、ACL 和最终状态。
  5. 可靠性与充分性：评分器校准、独立保留集、切片、重复和区间。

追踪链为：需求 → 决定 → 利益相关方 → 风险 → 构念 → 问题 → 场景 → 证据 → 门禁 → 动作。状态使用 covered、partial、blocked、out_of_scope；关键证据 blocked 时必须是 Inconclusive。

06 · 四类设计失效

代理指标失效
引用数、自动化率或总召回提高，不代表有据性、安全或可用性提高。
评测对象漂移
决策对象、运行对象、证据对象和报告结论不一致。
场景遗漏
随机流量样本遗漏低频高伤害、边界、异常、身份和攻击场景。
不可验证需求
“绝对安全”“零幻觉”需操作化；关键状态不可观察时先建设证据能力。

08 · 可执行实验

本实验评审设计产物，不声称已运行真实 Harness。

  1. 填写 Charter，锁定决定、范围和结果类型。
  2. 建立 stakeholder-impact chain 和风险陈述。
  3. 为关键风险操作化构念，并在 Charter 中写评测问题。
  4. 声明数据、场景、参考标准、观察、评分和充分性。
  5. 填写追踪矩阵，分别做需求向前和证据反向审查。
  6. 把链标为 covered、partial、blocked 或 out_of_scope。

完成标准：没有孤立关键风险和孤立门禁指标；Target 与决定一致；不可验证愿景被操作化或明确列为限制。

09 · 结果分析

结果证据含义动作
Pass声明范围证据充分且关键门禁满足只批准该范围
Fail确认关键门禁违反或不可接受退化阻断、修复、回归
Inconclusive版本、参考标准、观察或覆盖不足保持原权限并补证
Conditional Pass证据充分的子范围可明确隔离只开放该子范围

Conditional Pass 不能掩盖不可隔离的关键风险失败；任何结论都要声明不支持的推断、残余风险和重新评测触发条件。

10 · 单元测评与参考答案

  1. 十万条文档生成问答能证明真实覆盖吗？不能；它常遗漏无答案、权限、冲突和过期场景。
  2. 100% 引用率能证明有据性吗？不能；还需验证原子主张蕴含、完整性、版本和 ACL。
  3. 模型政策问答优秀能批准退款自动执行吗？不能；还要评测审批、工具、重试和最终账本状态。
  4. 关键状态无法观察怎么办？结论为 Inconclusive，并先建设观察和参考标准。
  5. 何时可 Conditional Pass？只有证据充分的子范围可清晰隔离且不绕过关键控制时。
  6. 无决策用途但有调试价值的指标怎么办？标为诊断指标，不参与门禁。
