AI 评测的本质

从“跑题得分”跨越到企业级质量工程：以决策为起点，以风险为约束，以实验产生证据，以门禁和监控触发行动。

核心命题：AI 评测不是单个指标，也不是一次测试；它是面向明确决策、能够复现与审计的实验性证据系统。

01 · 评测的可执行定义

在规定的对象、边界、场景、环境、样本和重复运行协议下，对 AI 系统产生的可观察证据进行评分和统计推断，并依据预先声明的风险容忍度作出发布、阻断、回滚、监控或改进决定。

层次关键问题交付物
决策证据最终支持什么动作？Evaluation Charter、Gate Policy
对象到底在评测什么版本和哪些组件？Evaluation Target
风险失败造成什么伤害，“好”是什么？Risk Definition、Metric Card
实验怎样稳定地产生可比较证据？Task Spec、Harness Manifest
处置结果超过边界后谁采取什么动作？Gate Decision、Monitoring Signal
没有决策的分数只是信息；没有可复现实验的分数只是一次观察；没有责任人与动作的告警只是噪声。

02 · 六问骨架

  1. 决定什么？发布、选型、灰度、回滚、训练数据采纳，还是风险接受？
  2. 最怕什么？幻觉、越权、泄露、偏见、任务失败，还是成本与延迟失控？
  3. 评测谁？裸模型、RAG、Agent、工具链，还是完整用户流程？
  4. 看什么证据？文本、引用、轨迹、工具调用、环境状态、延迟或人工结论？
  5. 证据多可信？样本代表性、重复运行、评分器可靠性与区间是否充分？
  6. 根据证据怎么办？通过、阻断、复核、灰度、回滚，还是生成回归任务？

03 · 模型、系统、产品与生产

工作类型关注点不能推出的结论
模型能力评测模型在固定能力任务上的表现完整产品可安全上线
系统评测模型、RAG、工具和策略的组合行为真实流量中没有新风险
产品验收与门禁目标业务场景是否满足风险边界上线后永远不退化
生产监控版本、流量和环境变化下的真实表现可以省略上线前高风险测试

对象边界一旦变化，证据含义也会变化。裸模型答案正确，不能证明检索索引没有污染、工具权限没有越界、工作流没有重试副作用。

04 · 从构念到门禁的测量链

构念

构念是希望测量但不能直接观察的属性，例如事实可靠性、合同风险识别能力或退款政策合规性。必须用定义、正例、反例和边界例固定含义。

评分器

评分器把一次运行的观察转成结构化分数。它可以是确定性规则、程序检查、人工标注或 LLM-as-Judge。评分器本身需要校准：Judge 可能有位置、长度和风格偏好；人工体系需要盲标、复核、仲裁与一致性分析。

指标

指标把多个样本的分数聚合为失败率、召回率、平均成本或尾延迟。任何指标都应声明分母、聚合层级、切片、缺失值、不确定性与版本。

门禁

门禁将证据转换为动作。严重风险通常不可补偿：一次真实越权操作不能被一百次措辞优秀的回答平均掉。

构念 → 可观察证据 → 评分器 → 样本级分数 → 聚合指标与区间 → 门禁规则 → 决策动作

05 · 随机性、经验分布与配对重采样

同一输入会因为生成采样、检索结果、工具状态、并发调度和 Agent 路径产生不同结果。单次运行是随机变量的一次观测，不是能力真值。

经验分布是固定协议下实际观测结果形成的分布。非参数重采样不先假设正态分布等特定分布族，而是从已有样本中有放回抽样，反复计算指标，估计指标在抽样变化下的分布。

配对重采样用于版本比较：基线与候选面对相同任务、种子和环境，对每一对结果先求差，再重采样这些差值对。它减少任务难度差异带来的噪声，更直接地估计版本变化。

240 次独立试验观察到零次严重事件，并不证明风险为零。用“3/n”粗略理解 95% 上界，仍只能说真实发生率大致低于 1.25%。

同一会话、文档或用户产生的样本通常相关。应按自然簇重采样，否则会把有效样本量估得过大、把置信区间估得过窄。统计显著性也必须与效果量、风险严重性和业务阈值共同解释。

06 · Agent Environment Harness

Agent 的最终文本可能与真实行为不一致。一个 Agent 可以先执行越权写操作，再在回复中声称“没有执行”。因此评测对象是策略在环境中的行为。

  • 环境生命周期：创建、初始化、隔离、重置、销毁。
  • 工具与权限：允许和拒绝列表、参数约束、副作用边界。
  • 完整观察：最终答案、轨迹、工具调用、资源消耗和最终状态。
  • 状态断言：数据库、文件、支付、工单和权限是否达到预期。
  • 故障注入：超时、权限拒绝、检索污染与依赖降级。
  • 预算与重放：约束步骤、时间和成本；将事故转成可重复回归任务。

07 · TEVV 与持续质量闭环

Testing在定义的输入和预期下发现实现缺陷。
Evaluation测量能力、风险与权衡，为决策形成证据。
Verification确认实现符合规格和执行协议。
Validation确认规格和证据适用于真实用途。
Monitoring上线后持续检测退化、新风险和分布变化。
Audit检查责任、程序、证据链与控制是否成立。
生产信号 → 事故调查 → 最小复现 → 受保护回归集 → 改进数据 → 训练 / 策略更新 → 完整门禁 → 灰度与监控

Eval-to-RL 可以使用失败挖掘结果，但训练集、调参验证集和最终门禁集必须隔离。否则系统用同一批证据训练并证明自己，造成测试污染和奖励投机。

09 · 八种常见失效

  1. 先选择指标，再倒推业务目标。
  2. 声称评测产品，实际只调用裸模型。
  3. 总体平均分掩盖关键风险和人群切片退化。
  4. 测试样本进入训练或提示词调试，造成污染。
  5. 把未经校准的 LLM Judge 当作客观真值。
  6. 每个样本只运行一次，忽略随机性。
  7. 环境、依赖、种子和状态无法重放。
  8. 监控告警没有负责人、时限、回滚和回归闭环。
高分不是安全证明。证据只在声明的对象、场景、样本、环境和时间边界内有效；边界变化后需要重新验证。
