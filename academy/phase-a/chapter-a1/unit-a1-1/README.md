# A1.1｜AI 评测的本质

> 本单元建立后续质量标准、LLM-as-Judge、Agent Environment Harness、CI/CD 门禁、生产监控和 Eval-to-RL 的共同语言。核心结论是：**AI 评测不是“跑一批题并计算分数”，而是为一个明确决策建立可审计的实验性证据系统。**

## 1. 学习目标

完成本单元后，应当能够：

1. 从业务决策出发定义评测，而不是从某个现成指标出发拼装报表。
2. 区分模型评测、系统评测、产品验收、上线门禁和生产监控。
3. 分清构念（construct）、评分器（scorer）、指标（metric）与门禁决策（gate decision）。
4. 解释随机性、样本、经验分布、不确定性区间和配对重采样的作用。
5. 对 Agent 同时观察最终答案、行为轨迹、工具调用和环境最终状态。
6. 将风险、任务、Harness、指标和处置动作连接成可追溯的证据链。

## 2. 一个可执行的定义

AI 评测可以写成：

> 在规定的对象、边界、场景、环境、样本和重复运行协议下，对 AI 系统产生的可观察证据进行评分和统计推断，并依据预先声明的风险容忍度作出发布、阻断、回滚、监控或改进决定。

这个定义包含五层：

| 层次 | 必须回答的问题 | 典型交付物 |
|---|---|---|
| 决策 | 证据最终支持什么动作？ | Evaluation Charter、Gate Policy |
| 对象 | 评测模型、RAG、Agent，还是完整产品？ | Evaluation Target |
| 风险与构念 | “好”具体指什么，失败造成什么伤害？ | Risk Definition、Metric Card |
| 实验 | 用什么任务、环境、样本与重复策略产生证据？ | Task Spec、Harness Manifest |
| 推断与处置 | 结果是否稳定，超过阈值后怎么办？ | Estimate、Gate Decision、Monitoring Signal |

如果缺少决策层，评测容易沦为指标展示；如果缺少实验层，分数无法复现；如果缺少处置层，发现问题也不会改变发布或运营行为。

## 3. 六问骨架

任何评测需求都可以先压缩成六个问题：

1. **决定什么？** 发布、选型、回滚、扩量、定价、训练数据采纳，还是风险接受？
2. **最怕什么？** 功能失败、越权操作、幻觉、偏见、泄露、成本失控或业务损失？
3. **评测谁？** 基础模型、提示词、检索链路、工具、Agent、工作流或端到端产品？
4. **看什么证据？** 最终答案、引用、工具调用、轨迹、状态变化、延迟、成本或人工判定？
5. **证据可信到什么程度？** 样本是否代表目标流量，随机性是否重复，评分器是否可靠，区间是否足够窄？
6. **根据证据怎么办？** 通过、阻断、人工复核、灰度、回滚、创建回归样本或进入改进闭环？

这六问不是文档格式，而是设计时的最小检查表。一个看似完整的评测方案，只要其中一问没有答案，就存在决策断点。

## 4. 四类工作不能混为一谈

| 类型 | 主要问题 | 对象边界 | 证据用途 |
|---|---|---|---|
| 模型能力评测 | 模型在某类能力上表现如何？ | 模型与推理参数 | 研究比较、模型选型 |
| 系统评测 | 组合系统是否完成任务并满足约束？ | 模型、提示词、RAG、工具、策略 | 工程优化、版本比较 |
| 产品验收与门禁 | 在目标业务风险下能否上线？ | 用户流程与依赖系统 | 发布、阻断、例外审批 |
| 生产监控 | 上线后是否退化或出现新风险？ | 真实流量、版本、地域、用户群 | 告警、回滚、调查、回归集扩充 |

离线高分不能自动推出“产品可上线”：测试样本可能不代表真实流量，Sandbox 可能没有覆盖依赖故障，平均分还可能掩盖关键风险。生产监控也不能替代上线前门禁，因为有些伤害不应通过真实用户试错来发现。

## 5. 构念、评分器、指标与门禁

### 5.1 构念（Construct）

构念是希望测量但不能直接观察的属性，例如“合同风险识别能力”“事实可靠性”或“退款政策合规性”。构念必须给出正例、反例和边界，否则不同的人会用同一个词描述不同目标。

### 5.2 评分器（Scorer）

评分器把一次运行的观察转换为结构化分数。例如：

- 确定性规则检查环境中是否真的创建了退款；
- 程序比较引用条款是否存在于给定合同；
- 人工标注员依据 rubric 判断风险是否遗漏；
- LLM-as-Judge 对解释完整性给出分档评分。

评分器本身也会犯错。LLM Judge 需要校准偏差、位置效应、长度偏好、自洽性和与人工金标的一致性；人工标注需要定义指南、培训、盲标、复核与仲裁。

### 5.3 指标（Metric）

指标把多个样本或重复运行的分数聚合为统计量，例如失败率、召回率、平均成本、尾延迟或关键风险发生率。指标必须同时声明分母、聚合层级、缺失值处理、置信区间和版本。

### 5.4 门禁（Gate）

门禁把指标转换为动作。高风险规则通常是**不可补偿的**：一次未经授权的真实退款，不能被大量措辞优美的回答平均掉。门禁因此至少需要：关键风险硬阈值、一般能力退化阈值、不确定性处理、例外审批、证据保留和失败后的动作。

## 6. 随机性与统计证据

同一个输入可能因为采样温度、服务端实现、检索结果、工具状态、并发调度或 Agent 决策路径而得到不同结果。一次运行是随机变量的一次观测，不是系统能力的完整真相。

### 6.1 经验分布

在固定协议下重复运行，得到的观测集合构成经验分布。它不预设结果服从正态分布，而是用实际样本近似未知的真实分布。我们关心的不只是平均值，还包括尾部、失败模式、方差和条件分组。

### 6.2 非参数重采样

“使用重采样方法对随机变量的经验分布进行非参数估计”可以拆解为：把已经观察到的样本当作对未知分布的近似，从这些样本中有放回地反复抽取同等规模的新样本，每次重新计算指标，观察指标在重复抽样下如何变化。它被称为非参数方法，是因为不先假设结果必须属于某个特定参数分布族。

### 6.3 为什么使用配对重采样

比较候选版本 A 与基线 B 时，应让两者面对相同任务、种子或环境条件，并对每个配对计算差值，再对“差值对”重采样。这样可以抵消样本难度差异，直接估计版本变化带来的效果。若分别独立抽样，任务难度噪声会混入版本差异，区间通常更宽，甚至产生错误方向。

### 6.4 区间、零事件与相关性

- 点估计只描述当前样本；置信区间描述在抽样不确定性下结果可能波动的范围。
- 观察到零次严重事故不等于真实风险为零。粗略的 95% 上界可用 `3 / n` 理解：240 次独立试验零事件，仍只支持真实发生率大致低于 1.25%，而不是证明绝对安全。
- 多轮对话、同一用户、同一文档切片或同一环境产生的样本往往相关。把它们当作完全独立会低估不确定性。应按会话、文档、用户或任务簇进行聚类重采样。
- 统计显著不等于业务重要；应同时报告效果量、风险严重性和决策阈值。

## 7. Agent Environment Harness 为什么是核心

对普通问答，最终文本有时足以评分；对 Agent，最终答案可能隐藏危险行为。例如 Agent 先执行了越权写操作，再在文本中声称“未执行”。因此 Harness 至少要控制并记录：

1. **环境生命周期**：创建、初始化、重置、隔离和销毁。
2. **工具与权限**：允许列表、拒绝列表、参数约束和副作用边界。
3. **可复现输入**：任务、数据夹具、时间、随机种子和依赖版本。
4. **完整可观察性**：最终答案、轨迹、工具调用、资源消耗和环境状态。
5. **状态断言**：数据库、文件、工单、支付或权限是否达到预期状态。
6. **故障注入**：超时、空检索、权限拒绝、工具返回污染和依赖降级。
7. **预算约束**：步数、时间、Token、调用次数和成本上限。
8. **重放能力**：把生产事故转成可重复的回归任务。

真正的 Agent 评测对象是“策略在环境中的行为”，而不只是文本生成模型。

## 8. TEVV 与持续质量闭环

| 活动 | 核心含义 |
|---|---|
| Testing | 在已定义输入和预期下发现实现缺陷 |
| Evaluation | 测量能力、风险与权衡，形成决策证据 |
| Verification | 证明实现是否符合规格与协议 |
| Validation | 证明规格与证据是否适用于真实用途 |
| Monitoring | 上线后持续检测退化、新风险和分布变化 |
| Audit | 检查责任、程序、证据链和控制是否成立 |

完整闭环不是“评测结束即完成”，而是：生产信号触发调查，确认的事故进入回归集，评测失败形成改进样本，改进后的模型或策略重新经过受保护的门禁，再进入灰度和监控。Eval-to-RL 位于这个闭环中，但训练集、验证集和最终门禁集必须隔离，避免用同一证据既训练又证明自己有效。

## 9. 两个端到端案例

### 9.1 退款 Agent

决策是“版本 2 是否允许上线处理真实退款”；首要风险是未经授权产生退款。评测对象包括模型、提示词、政策层、工具定义和 Sandbox。证据同时包括文本、轨迹、工具调用与支付状态。关键风险采用零容忍、不可补偿门禁；生产侧对退款事件全量监控，并在违规时冻结灰度、通知负责人、创建回归样本。

完整结构见 [退款 Agent 案例](examples/refund-agent/evaluation-case.yaml)，对应通用模板从 [Evaluation Charter](evaluation-charter.yaml) 开始。

### 9.2 合同审查 Agent

决策是“能否用于高价值采购合同的首轮风险筛查”；首要风险包括遗漏无限责任、伪造不存在的条款和在不确定时不给出升级建议。这里不能只计算整体准确率：关键条款漏检需要单独硬门禁，引用必须能回到原文位置，不确定案例要升级给法务。完整结构见 [合同审查 Agent 案例](examples/contract-agent/evaluation-case.yaml)。

## 10. 常见失效方式

1. **从指标开始**：先决定“用 BLEU、胜率或 Judge 分数”，却没有定义业务决策和风险。
2. **对象漂移**：声称评测产品，实际只调用了裸模型，绕过 RAG、权限和工具。
3. **平均数遮蔽风险**：总体分数上涨，但关键人群、关键语言或高风险任务退化。
4. **测试集污染**：题目进入训练或提示词调试，分数上涨不再代表泛化。
5. **评分器未经评测**：把 LLM Judge 当作客观真值，没有金标、校准或偏差分析。
6. **忽略随机性**：每个样本只跑一次，无法知道结果是否稳定。
7. **环境不可复现**：依赖版本、时间和状态未锁定，失败无法重放。
8. **有告警无动作**：监控指标没有负责人、处置时限、回滚路径和回归闭环。

## 12. 单元结论

一项企业级 AI 评测必须形成以下闭环：

```text
业务决定 → 风险与构念 → 被测对象与边界 → 任务、样本与 Harness
       → 观察与评分 → 统计推断 → 质量门禁 → 生产监控 → 事故回归与改进
```

评测的价值不在于产生更多分数，而在于让高风险决策拥有可复现、可质疑、可审计并能触发行动的证据。
