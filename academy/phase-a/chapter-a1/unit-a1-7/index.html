01 · 从 Score 到 Metric Quality Gate

A1.6 Score Records → Metric Definition → Population & Denominator → Aggregation → Uncertainty → Analysis Plan → Estimate → Comparison → Metric Quality Gate → Future System Gate

A1.6 裁决一次具体运行；A1.7 定义跨样本统计证据。Score 没有总体和分母，Estimate 必须绑定 Dataset、Target、Scorer、Harness、Metric 与分析代码，Metric Gate 只决定证据是否有资格进入系统决策。

02 · Construct、Estimand、Estimator、Estimate

Construct
希望测量的抽象属性，例如安全任务有效性。
Estimand
目标总体、条件、分析单位和真正待估的量。
Estimator
用有限样本估计目标量的方法。
Estimate
某次版本化数据与分析得到的实际结果。
Estimand 是问题，Estimator 是方法，Estimate 是结果；“准确率”不能同时代替三者。

03 · 总体、分析单位与分母

分母来自 Estimand，不是清洗后剩余的数据。必须预声明纳入、排除和 timeout、crash、system abstention、scorer abstention、unscorable、inconclusive 的处理，并报告 sampled → executed → failed → abstained → unscorable → scored 的完整流转。

状态语义不能做什么
system failure被测系统超时、崩溃或超预算因无答案而删除
system abstention系统主动拒答或升级自动算通过或失败
scorer abstention评分器识别越界冒充候选零分
unscorable身份、观察或 Reference 不满足前提记零或静默删除
inconclusive完整流程后仍不足以下结论强制二元化

04 · 聚合、权重与辛普森悖论

Micro 让高频单位权重大；Macro 让切片等权；Target-weighted 估计声明的目标分布；Conditional Metric 直接描述风险触发条件。它们回答不同问题，没有脱离 Estimand 的“最佳平均”。

候选总体分数可以因简单任务占比上升而提高，即使每个难度切片都退化。版本比较应使用相同任务、相同目标权重和配对设计，并强制报告关键切片。

一份合同的二十个 claim 不是二十份独立合同；一百个任务各五次运行不是五百个独立业务场景。

05 · 随机性、依赖与 Bootstrap

不确定性来自任务抽样、模型执行、环境和评分器。重采样必须保持原始依赖结构。

结构方法
相对独立任务普通 Bootstrap
同任务版本比较Paired Bootstrap
任务内重复运行Cluster Bootstrap
配对且有重复运行Paired Cluster Bootstrap
任务家族—任务—运行Hierarchical Bootstrap
时间相关生产流量Block / time-aware Bootstrap

Bootstrap 不能修复总体不代表、极小样本、未观测罕见风险、分布漂移、错误 cluster key、评分器偏差或选择性报告。零事件需报告精确区间或 3/n 上界，不能宣称零风险。

06 · 效果量与决策边界

比较问题可能是优效、非劣效、等效或绝对达标。必须同时报告绝对与相对效果、区间和预定义的业务意义边界。

Superiority
区间是否支持正向效果，并达到最小有意义改善。
Non-inferiority
最不利区间是否仍未跨越允许退化界值。
Equivalence
完整区间是否落在预定义等效范围。
Absolute threshold
候选即使优于基线，也必须满足使用底线。

统计显著不等于值得上线；没有显著差异也不证明等效。关键事件本身可以触发阻断，不以 P-value 作为免责条件。

07 · 缺失、弃权与选择偏差

缺失可以是完全随机、条件随机或非随机。AI 系统最危险的是非随机缺失：越危险的运行越容易超时、崩溃、丢日志或让 Judge 拒判。只分析成功评分样本会产生幸存者偏差。

同时报告 conditional pass rate、scorable coverage、不可评分原因和缺失全通过/全失败上下界。选择性回答系统还需报告 Coverage、Selective risk、正确/错误弃权、人工负担和 Coverage–Risk 曲线。

08 · 多重比较、停止与赢家诅咒

二十个独立 5% 检验在真实无差异时，至少一次偶然显著的概率约为 64%。确认性指标、切片、阈值、样本量、调整方法和停止规则必须在执行前声明；探索发现需要独立确认。

Holm、Bonferroni、FDR 或同时区间服务于不同错误控制目标。反复查看直到显著再停止属于 optional stopping；从大量候选中只报告最佳者会产生 winner's curse。

09 · Metric Quality Gate

状态允许动作
ready进入声明范围的系统 Gate 输入
partial仅在独立证据支持的子范围使用
blocked补充身份、覆盖、Scorer、依赖或不确定性证据
invalid隔离被污染、错配、错误或选择性报告的版本
Scorer Quality Gate → Metric Quality Gate → System Release Gate

本单元模板没有真实 Score 或 Estimate，所有案例诚实保持 blocked。

12 · 明确证据边界

本候选包证明课程、模板、案例和内部追踪合同形成；不证明 A1.5 数据物化、A1.6 Scorer 实现或就绪，不证明真实 trial、Score、Estimate、Comparison、Harness、统计结论或系统发布 Gate，也不证明生产表现或个人能力。

没有总体、分母、依赖、不确定性和身份绑定，平均数只是失去上下文的计算；具备这些合同，Score 才能成为可复现、可质疑和可审计的统计证据。
