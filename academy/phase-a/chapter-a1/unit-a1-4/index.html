从评测问题到任务与场景

让风险、状态、时间、故障和行为约束进入任务设计，使每次运行都能产生与决策相关的证据。

核心命题：Task Spec 不是提示词，Test Case 也不只是问题文本；Agent 任务还包括环境初态、权限、工具、轨迹和最终状态。

01 · 从问题到一次运行

Evaluation Question → Scenario Space → Task Spec → Test Case → Variant Family → Trial → Observation → Decision Evidence

Evaluation Question 固定构念与决策用途；Scenario Space 定义会改变风险或期望行为的轴；Task Spec 定义一类任务的可执行合同；Test Case 固定一次运行的输入与状态；Variant Plan 描述样本之间的受控关系；Trajectory Contract 约束允许路径；Coverage Matrix 记录真正覆盖与空白。

02 · 风险驱动的场景空间

场景轴典型取值风险用途
身份权限授权、未授权、失效决定可见信息和动作
输入完整、缺失、冲突、污染触发澄清、拒答或升级
状态与时间初始、完成、未知；边界前后检验合法性、幂等和生效规则
依赖正常、超时、拒绝、部分失败检验停止、恢复和升级
交互并发多轮更正、重复、并行、乱序暴露旧状态、重复副作用和竞态
对抗越权诱导、注入、伪造证据检验控制是否真正生效

场景空间不是所有轴的笛卡尔积。优先选择高严重性风险、强交互组合、决策边界和历史事故，并另设流量代表性分区。

03 · Task Spec 与 Test Case

Task Spec 的最小合同包含：评测问题与风险引用、actor 与权限、前置状态、输入契约、可用动作、成功与最终状态、停止和升级、观察、预算、重置与重放。

“表现专业”不可执行；“风险候选包含原文 span，附件缺失时不得给出最终结论并创建律师复核项”是可观察合同。

Test Case 引用 Task Spec，并固定场景坐标、fixture、initial state、stimulus、期望、禁止行为和 evidence IDs。代表性、风险定向、边界、回归和对抗样本用途不同，不能共享同一发生率分母。

04 · 受控、反事实、不变与变形

Controlled
一次只改变一个可解释变量，其他因素保持固定。
Counterfactual
仅改变角色或关键事实，并预先声明结果应如何变化。
Invariant
同义改写或无关顺序变化后，核心决定与状态保持一致。
Metamorphic
跨金额、权限或时间边界时，输出按已知规则切换。

这些关系能提供结构化检查，但关系本身必须经领域确认，不能通过同时改变多个变量制造不可解释差异。

05 · 多轮、状态、时间、故障、并发与轨迹

初始状态 → 用户请求 → 读取与授权 → 工具调用或澄清 → 返回或故障 → 核验、停止、恢复或升级 → 最终回答与最终状态

超时不等于未执行；未知结果不能盲目重试；并发请求需要幂等键和最终状态断言；后续更正必须覆盖旧信息。Trajectory Contract 规定动作顺序、允许工具、写入前置条件、重试上限、恢复不变量和停止条件。

轨迹合同只约束外部可验证行为，不要求披露模型内部思维过程。最终答案正确也不能补偿危险工具副作用。

06 · Coverage Matrix

矩阵连接 question、risk、task、case、scenario family、variant、transition 与 evidence。状态区分 planned、implemented、executed、blocked 和 excluded；计划或实现不等于证据有效。

  • 关键风险至少有正向、负向、边界、故障和恢复场景。
  • 身份、领域、时间和权限切片有明确覆盖或排除理由。
  • 关键门禁存在可触发失败条件的样本。
  • 代表性样本与风险定向样本分母分开。
  • 样本数量不能单独证明关键风险 covered。

08 · Task Spec 质量门与实验

进入后续工程前，确认每个任务可追踪到问题、风险和构念；前置状态可重建；成功、失败、停止和升级可观察；权限、副作用、预算和最终状态有合同；关键风险组合进入矩阵。

  1. 从一个 Evaluation Question 生成风险场景轴与分区。
  2. 填写 Task Spec，并实例化一个常规和一个关键边界案例。
  3. 构造反事实、不变和变形关系。
  4. 为 Agent 填写轨迹与恢复不变量。
  5. 更新 Coverage Matrix，解释所有关键空白。
  6. 关键项 blocked 时停止进入数据、Scorer 或 Harness 实现。

本实验只设计任务资产，不声称已运行真实 Harness。

09 · 结果分析

发现解释与动作
常规覆盖充分，超时场景为空一般表现可估计，状态安全 Inconclusive；补故障任务。
只改角色仍泄露相同内容反事实失败；关键权限风险 Fail。
同义改写导致决定波动不变关系失败；扩展变体并定位问题。
金额跨阈值后切换为升级变形关系满足，但不推广到其他政策。
高风险格子仅 implemented尚无有效运行证据，不得声称 covered。

10 · 单元测评与参考答案

  1. 场景空间需要穷举吗？不需要；按风险、边界、交互和流量选择，记录排除理由。
  2. Task Spec 是提示词吗？不是；它包含状态、动作、成功和观察合同。
  3. 答案正确但轨迹违规能通过吗？不能，过程安全风险不可补偿。
  4. 风险定向集能估计生产失败率吗？不能，它刻意富集风险。
  5. 反事实对可同时改角色和措辞吗？不宜，否则无法归因。
  6. 超时后重试成功一定通过吗？不一定，先前调用可能已有副作用。
  7. implemented 等于 covered 吗？不等于；还需执行且证据有效。

明确边界

本单元不展开数据采集、清洗、标注与版本治理；不设计 Scorer、rubric、Judge 校准和统计聚合；不实现 Harness、工具模拟器、隔离或执行引擎。

延伸阅读包括组合测试、property-based testing、metamorphic testing、状态机测试与并发线性化；使用时应结合具体风险，而不是机械追求组合数量。

结论：任务设计必须说明风险在什么场景和状态下被触发，Agent 可以走什么路径，哪些行为必须或不得发生，什么最终状态构成成功，以及案例共同覆盖了问题的哪一部分。
