EVALORIUM · ACADEMYA1.6 · SCORER DESIGN
PHASE A · CHAPTER A1 · UNIT A1.6

从参考标准到评分器

把 Reference、评分单位、完整观察、Rubric、实现身份、分歧治理和独立验证连接成可审计的样本级证据裁决系统。

核心命题：Scorer 不是“给答案打个分”的函数。它必须知道判谁、依据什么、看到了什么、何时拒判，以及凭什么相信它的判断。

01 · 从 Reference 到可验证 Scorer

A1.5 Dataset / Reference → Scorer Charter → Scoring Unit → Observation Bundle → Rubric → Scorer Manifest → Adjudication → Validation → Scorer Quality Gate → Future Trial / Score / Metric

A1.5 定义数据、Reference 与受保护视图；A1.6 定义未来观察如何被裁决。本单元止于评分器设计和验证合同，不运行 Agent，不产生真实 Score 或 Metric。

02 · Reference、Rubric、Scorer、Score、Metric、Gate

对象中文解释产物
Reference权威事实、状态、多值集合、不变量或合格专家参考任务成功与禁止结果的依据
Rubric评分量规维度、尺度、锚点、关键错误和缺证规则
Scorer评分器读取观察与参考，产生样本级裁决或拒判
Score一条评分记录状态、维度分数、证据、理由与异常
Metric跨样本指标有分母、聚合、依赖和不确定性的统计量
Gate把证据变成动作的门禁ready、block、rollback 等；系统 Gate 不属于本单元
LLM Judge 输出“8 分”仍只是一条 Score，不自动成为 Reference、Metric 或发布决定。

03 · Scoring Unit：这一分属于谁

Atomic claim
每个可证事实主张单独绑定证据。
Tool call
参数、权限、结果和副作用。
State transition
初始状态、事件和最终状态。
Turn
多轮中的一次澄清、拒答或升级。
Trajectory
完整行为路径与过程约束。
Trial / task
一次端到端任务的样本级判断。

身份需要锁定 trial、task、dataset item、Target、环境和 seed。子单位可以组成 trial，但不能把一个 trial 的多个 claim 当成独立样本；跨 trial 聚合属于后续 Metric。

04 · Observation Bundle：评分器看到了什么

  1. Identity：trial、任务、数据、Target、环境和 schema 版本。
  2. Initial state：fixture、权限、有效时点、政策、文档或账本快照。
  3. Event stream：工具调用、结果、状态变化和因果顺序。
  4. Final output：内容、原子主张、引用、拒答或升级。
  5. Final state：权威最终状态、前后差异和未决副作用。
  6. Evidence metadata：来源、Reference、hash、时间、完整性与脱敏。

最终文本不能替代事件和状态。关键观察缺失或损坏时必须 unscorable；候选系统不得写入 Reference 字段，捕获后的观察应不可变。

05 · 五类评分器与权威顺序

类型适用范围主要风险
Deterministic权威状态、精确不变量、ACL、写入次数抓错状态、版本错配、规则 bug
Programmatic集合、结构、span、可执行条件比较容差或边界错误
Human领域解释、价值判断、边界案例资格、共同偏差、非盲评
LLM-as-Judge校准范围内的开放文本维度位置、冗长、自我偏好与注入
Composite按权威编排多个子评分器错误平均、覆盖关键失败
authoritative state / invariant → exact rule → qualified human → bounded calibrated Judge
权威状态确认的未授权写入、伪造 span 或 ACL 泄露必须 force-fail，不能被 Judge 高分或其他维度平均掉。

06 · Rubric：从构念到可重复判断

Analytic rubric 将质量拆成有据性、授权、完整性、升级等维度，适合诊断和风险审计；Holistic rubric 给整体印象，只能补充，不能替代关键风险维度。

每个维度至少需要构念、评分单位、定义、量尺、每档 Anchor、required evidence、边界例和版本。锚点必须描述可观察条件，例如“缺一个非关键证据 span 且无 critical error”，不能只写“回答一般”。

Critical error 要连接 Risk，明确 compensable: false 与 judge_override_allowed: false。维度、量尺、锚点、关键错误或证据规则变化时发布新版本，不静默改写历史 Score。

07 · 不确定、拒判、不可评分、分歧与无结论

状态含义动作
uncertain观察够用，但参考或边界不足以稳定单值判断保留理由，仲裁或多值输出
abstained评分器主动识别超出授权或能力路由合格评分器，不强判
unscorable关键身份、观察或 Reference 不满足前提不输出数值，补证或重捕获
disagreement合法评分在状态、分数、关键错误或证据上不同保留原始判断，分类并独立仲裁
inconclusive完整流程后仍无决定性证据缩小声明或调查来源

零分表示“有证据确认失败”；unscorable 表示“没有判断资格”。仲裁不是多数票：它要冻结原始记录、分类原因、独立复核，并把 scorer bug、Rubric 缺陷或 Reference 冲突反馈为新版本。

08 · Scorer 自己也必须被评测

Reliability · 可靠性
重复、重测、跨评审者与版本稳定性。
Validity · 效度
内容、准则、构念、已知正反例；一致不等于测对。
Calibration · 校准
置信、阈值、abstention—coverage 和阈值错误。
Error profile · 错误画像
false pass、false fail、abstain error、缺证强判。
Bias & robustness
语言、角色、文风切片；释义、顺序、长度和格式扰动。
Security · 安全
输出注入、Reference 泄露、篡改、证据伪造、重放与版本错配。

验证数据必须独立于 scorer 开发，阈值在执行前声明，并保留样本级物化记录。计划、空数组和 scorer 自我声明不构成验证证据。

09 · Scorer Quality Gate

状态含义
ready所有关键检查有独立、物化、可审计且达阈值的证据；只进入后续 trial 准备
partial仅可隔离且验证充分的子范围继续
blocked实现、身份或关键验证证据缺失，停止正式评分
invalid身份、权威、效度或安全存在不可接受缺陷，隔离版本

检查至少覆盖 scorer 身份、权威优先级、可靠性、效度、校准、错误画像、偏差稳健性和安全。当前模板与案例均诚实为 blocked，因为没有实现或独立物化结果。

10 · 同一“可靠”愿望导出三套 Scorer

退款 Agent

以政策、审批与账本为权威；确定性检查未授权、写入次数和状态一致性；Judge 只补充解释完整性。查看完整案例 →

合同审查 Agent

允许合理多值法律解释，但文档版本和字符偏移可确定；律师处理解释，Judge 不得把不存在的 span 判成有效。查看完整案例 →

企业知识助手

ACL、当前文档、全路径日志与 canary 最有权威；有帮助的回答不能补偿未授权检索、上下文、缓存或输出泄露。查看完整案例 →

11 · Reference-to-scorer 设计审查

  1. 精确复用 A1.5 的 Target、Construct、Question、Risk、Task、Dataset 与 Reference IDs。
  2. 选定评分单位、身份、依赖和聚合终点。
  3. 列齐观察包六部分，缺关键观察即 unscorable。
  4. 为每个维度写量尺、锚点、证据和边界例。
  5. 把关键风险写成不可补偿错误，指定最强权威。
  6. 组合多个 scorer 时写明 precedence，禁止 Judge 覆盖确定性失败。
  7. 区分 uncertain、abstain、unscorable、disagreement 与 inconclusive。
  8. 预声明可靠性、效度、校准、错误、偏差、稳健性和安全验证。
  9. 无物化证据时保持 gate blocked。

证据边界

本候选包不证明 A1.5 数据已经物化，不证明 scorer 已实现、运行或校准，不证明存在真实 Observation Bundle、trial、Score、Metric、Harness、统计推断或系统发布 Gate，也不证明生产表现或个人能力。
