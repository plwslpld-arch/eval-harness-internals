# Security Policy

## Supported versions

Evalorium is pre-release. Only the current `main` branch is considered for security fixes.

## Reporting a vulnerability

Do not open a public issue for vulnerabilities, credential exposure, unsafe evaluation fixtures, sandbox escapes, or data leakage.

Use GitHub private vulnerability reporting when it is enabled for the repository. If that option is unavailable, contact the repository owner through the contact methods published on the [`plwslpld-arch` GitHub profile](https://github.com/plwslpld-arch). Do not send live secrets or sensitive datasets until a secure channel has been agreed.

Include the affected commit, environment, reproduction steps, impact, and the smallest safe proof of concept. Remove tokens, personal data, proprietary content, and unnecessary exploit details.

## Credential exposure

Any credential pasted into a conversation, log, issue, or commit must be treated as compromised. Revoke and rotate it; deleting the visible text alone is not sufficient.
