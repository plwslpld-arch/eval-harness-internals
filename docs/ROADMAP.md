# Roadmap

Roadmap completion is evidence-based. Dates may guide pacing, but a milestone exits only when its deliverables and validation evidence exist.

## M1 — Academy Foundation

**Entry:** public repository and approved product direction.

**Deliverables:** curriculum map, unit protocol, assessments, labs, competency matrix, handoff workflow, bilingual project documentation, and repository quality gate.

**Evidence:** every completed public unit has versioned artifacts, a passing artifact contract, documented limitations, and traceable progress state. Personal competency assessment is tracked separately when such a claim is needed.

**Exit:** foundation process is reproducible on another computer and the initial phase capstone can begin.

## M2 — Eval Core Alpha

**Entry:** core evaluation concepts and measurement foundations completed.

**Deliverables:** task, dataset, runner, solver, scorer, adapter, structured result, and reproducible execution interfaces.

**Evidence:** unit and integration tests, deterministic fixtures, example evaluations, versioned result schema, and baseline comparison.

**Exit:** a model or RAG system can be evaluated end to end with reproducible artifacts.

## M3 — Measurement and Judge Reliability

**Deliverables:** paired comparisons, bootstrap intervals, effect sizes, sampling tools, judge calibration, bias studies, human evaluation workflow, and adjudication.

**Evidence:** simulation tests, calibrated datasets, judge-human agreement analysis, and documented limitations.

**Exit:** gate decisions include uncertainty and evaluator reliability rather than point estimates alone.

## M4 — Agent Environment Harness Beta

**Deliverables:** sandbox lifecycle, task environments, tool policies, state assertions, trace schema, budgets, fault injection, replay, and trajectory scoring.

**Evidence:** reproducible agent tasks, reset isolation tests, security tests, long-running failure recovery, and comparative agent benchmarks.

**Exit:** agents are scored on environment state, behavior, safety, and efficiency—not only final text.

## M5 — Security and Quality Gates

**Deliverables:** threat model, adversarial suite generation, permission tests, CI/CD gates, baselines, exceptions, review policy, and rollback evidence.

**Evidence:** red-team regressions, blocked unsafe changes, reviewed waivers, and gate decision audits.

**Exit:** evaluation is a mandatory, enforceable release prerequisite.

## M6 — Production Monitoring and Governance

**Deliverables:** quality telemetry, drift and hallucination monitoring, incident workflow, sampling policy, ownership, approvals, and evidence retention.

**Evidence:** replayed incidents, alert precision analysis, version-linked regressions, and governance reviews.

**Exit:** production failures reliably create accountable actions and new regression coverage.

## M7 — Eval-to-RL Integration

**Deliverables:** failure mining, preference and verifier datasets, reward exports, training curricula, holdout protection, and post-training gates.

**Evidence:** versioned exports, contamination tests, reward-hacking checks, and measured post-training improvement without protected regressions.

**Exit:** evaluation evidence can safely drive model or policy improvement.

## M8 — Ecosystem and Production Evidence

**Deliverables:** stable releases, external adapters, contribution governance, migration policy, real pilots, and public case studies where permitted.

**Evidence:** independent users, reproducible deployments, issue resolution history, release compatibility, and measured business or risk outcomes.

**Exit:** production-proven claims are supported by external evidence rather than repository activity alone.
